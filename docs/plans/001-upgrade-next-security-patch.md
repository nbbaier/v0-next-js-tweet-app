## Why this matters

`pnpm audit` reports a HIGH-severity advisory against the installed `next@16.2.5`:
"Next.js has a Middleware / Proxy bypass in App Router applications via
segment-prefetch routes — Incomplete Fix Follow-Up" (GHSA-26hh-7cqf-hhc6),
vulnerable range `>=16.0.0 <16.2.6`, patched in `>=16.2.6`. This app defines no
`middleware.ts`, so the practical exposure today is limited, but the app is
deployed publicly on Vercel and the patch is a one-line semver-compatible bump.
There is no reason to stay on a flagged version.

## Current state

- `package.json:22` — `"next": "^16.2.5"`; the lockfile resolves `next@16.2.5`
  (verified via `pnpm list next` → `next@16.2.5`).
- `pnpm audit` exits non-zero with 3 findings; the only HIGH one is the `next`
  advisory above (paths `.>next` and `.>@vercel/analytics>next`).
- At plan time `pnpm outdated` showed `next 16.2.5 → 16.2.7` available.
- `pnpm-workspace.yaml` (committed version) sets `minimumReleaseAge: 10080`
  (minutes = 7 days). pnpm will refuse to resolve versions published more
  recently than 7 days ago. 16.2.6/16.2.7 were already published before
  2026-06-10, so this should not block, but see STOP conditions.
- This repo has no tests and (until plan 003 lands) `next build` does **not**
  type-check (`next.config.mjs` sets `typescript.ignoreBuildErrors: true`), so
  verification is: install, audit, typecheck, build.

## Steps

### Step 1: Bump next

Edit `package.json:22` from `"next": "^16.2.5"` to `"next": "^16.2.6"`, then run
`pnpm install` (this updates the lockfile to the newest allowed 16.2.x).

**Verify**: `pnpm list next` → shows `next@16.2.6` or higher.

### Step 2: Confirm the advisory is resolved

**Verify**: `pnpm audit 2>&1 | grep -c "GHSA-26hh-7cqf-hhc6"` → `0`.
(Other advisories — `postcss` via next's pinned transitive, `brace-expansion`
via ultracite — may remain; they are known, dev-time-only, and out of scope.)

### Step 3: Typecheck and build

**Verify**: `pnpm exec tsc --noEmit` → exit 0.
**Verify**: `pnpm build` → exit 0. If `.env.local` is absent in your
environment, skip the build, note it in your report, and rely on typecheck.
