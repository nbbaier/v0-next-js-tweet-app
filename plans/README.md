## Findings considered and rejected

(Recorded so future audits don't re-litigate them.)

- **".env.local secrets committed to git history"** — false alarm from a
  subagent. `git log --all -- .env.local` is empty; the file was never
  tracked, and `.gitignore` covers `.env*`. No rotation or history rewrite
  needed.
- **"Stale seen/saved served from the tweet cache for up to 1 hour"** — false.
  `fetchTweetsWithCache` (lib/tweet-service.ts:84-98) always bulk-fetches
  fresh metadata and overlays it onto cached content; the Redis cache
  effectively stores content only.
- **Unauthenticated SSE endpoint (`/api/realtime`)** — by design. The home
  page is public and renders everything the events expose; adding auth would
  break the public feed for no confidentiality gain.
- **API secret in localStorage** — accepted trade-off for a personal app
  (XSS-exposure concern); revisit only if untrusted HTML rendering is added.
- **GET /api/tweets unpaginated** — returns IDs only (small payload), and the
  endpoint is debug-only; pagination not worth it at this scale.
- **Micro-perf items** (framer-motion `layout` on list items, `countByPoster`
  memoization, realtime event batching/debouncing) — speculative, unmeasured,
  low value at current feed sizes. Not worth doing now.
- **Tweet normalization duplication** (`normalizeTweetBase`/`normalizeTweetContent`)
  — mild, intentional layering for quoted tweets; not worth a refactor.
- **TypeScript 6.0.3 "too new"** — not actionable; monitor only.
- **Optimistic-update vs realtime-event race** in the feed — real but
  low-severity (self-heals; rollback exists). Revisit after 003/006 land and
  the hook has a single subscription to reason about.
